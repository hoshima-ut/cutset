# 編集ソフト間の引き継ぎの要件（UX-15）

[要件](requirements.md) ・ [設計](design.md) ・ [作業・試験](tasks.md) ・ [分野一覧](../README.md)

## 目的と範囲

Cutsetで作った編集をPremiereの編集者が引き継いで続きを編集でき、逆にPremiereで作った編集をCutsetで続けられるようにする。成果はファイル形式ではなく「受け取った人が、同じフレーム・同じ構成のまま、短い手直しで続きの編集を始められること」で測る。引き継げない要素は、渡す前と受け取った後の両方で一覧に示す。

対象は単独のファイルで受け渡す案件。Premiereのチーム共同編集・クラウド共有・プロダクション機能への参加、他アプリとの動的な連携は対象外。

## 受入条件

基準案件A・B（[作業・試験](tasks.md#具体的な試験)）を両方向で引き継ぎ、要素ごとの判定を[引き継ぎ表](design.md#引き継ぎ表)に記録する。合否は分類ごとに次で決める。

- **骨格**：すべて「そのまま」。カット点・In/Out・シーケンスの開始タイムコード（ドロップ／ノンドロップを含む）は両方向で0フレーム差。音声は全チャンネルが元と同じトラック・チャンネルに割り当たる。
- **編集の詳細・音**：「欠落」と「値違い」が0件。「手直し」は1案件あたり合計15分以内。
- **画・文字・整理**：「値違い」が0件。「欠落」は書き出し前の一覧と読込後の報告の両方に出ていれば可とし、件数を記録する。
- **受け手の時間**：受け取ってから続きの編集を始めるまでと、手直しの時間の合計が、両方向とも30分以内なら合格、60分を超えたら不合格、その間はオーナーが判断する。

時間の数値は仮置きで、段階H1の実測後にオーナーが決め直す。

要素一覧（分類と要素キー。キーは取込報告・引き継ぎ表で共通に使う）：

| 分類 | 要素 |
| --- | --- |
| 骨格 | シーケンス設定（解像度・フレームレート・ドロップ／ノンドロップ・音声サンプルレート）`skeleton.sequence`、開始タイムコード `skeleton.start_tc`、カット・In/Out `skeleton.cut`、トラック構成 `skeleton.tracks`、リンクした音声 `skeleton.link`、空白 `skeleton.gap`、複数シーケンス `skeleton.sequences`、ネスト `skeleton.nest`、素材の参照とソースタイムコード `skeleton.media`、音声チャンネルの割当（モノラル分割・ステレオ組・チャンネル数）`skeleton.channels` |
| 編集の詳細 | 速度・逆再生・静止 `edit.speed`、クロスディゾルブとディップ（黒）`edit.transition`、シーケンスとクリップのマーカー `edit.marker`、フレームレートの違う素材の混在 `edit.mixed_rate`、可変フレームレート素材 `edit.vfr` |
| 音 | 音量・パンの値とキーフレーム `audio.level`、フェード `audio.fade` |
| 画 | 位置・スケール・回転・不透明度の値とキーフレーム `picture.motion`、明るさ・コントラスト・彩度 `picture.basic_color` |
| 文字 | 字幕トラック `text.captions`、1行のテロップ（書体・大きさ・位置・文言）`text.title` |
| 整理 | ビン `organize.bin`、ラベル色 `organize.label`、クリップ名・シーケンス名（日本語を含む）`organize.name` |

Premiere由来でCutsetに同等の部品がない要素は、H1で実測してから扱いを決める。既定案は設計の[相手側由来の要素](design.md#相手側由来の要素)にある。

## 例外と復旧

相手側が表現できない要素を黙って落とさず、書き出し前に一覧で示し、焼き込み・別ファイル化・省略を選べるようにする（[受け渡しの選択](../受け渡しの選択/requirements.md)）。受け取った案件は原本を書き換えずに新しい未保存のCutset案件として開く。未確認の版・壊れたファイル・想定外の構造は理由を示して開かず、Premiere側でXMLを書き出して開く代わりの経路を案内する。往復して戻った案件は[往復後の差分](../往復後の差分/requirements.md)で変更点を確かめられる。
