# prproj案件の読込の設計（IO-57）

[要件](requirements.md) ・ [設計](design.md) ・ [作業・試験](tasks.md) ・ [分野一覧](../README.md)

## 操作と状態遷移

編集者は「ファイル ▸ 読み込み」または「開く」で `.prproj` を選ぶ。Cutsetは保存版を判定し、対応版なら新しい未保存のCutset案件を作って取り込み、再現できなかった要素の一覧を表示する。未対応版や壊れたファイルでは、案件を変えずに理由を表示する。CLIとエージェントは同じ取込命令を呼び、案件IDと一覧をJSONで受け取る。

```text
 .prproj（原本・読み取りのみ）
   │
   ▼
 [1 容器]  gzip展開・サイズ／入れ子の上限 ── 壊れている → 理由を返して終了
   │
   ▼
 [2 版判定] 保存版を読み、確認済みの版だけ通す ── 未確認 → 理由を返して終了
   │
   ▼
 [3 構造の読取] XMLの要素と相互参照を、見本から確かめた範囲だけ型に起こす
   │
   ▼
 [4 対応付け] 共通のタイムライン形式へ（FCP7 XML・AAF と同じ受け口）
   │                         └─ 再現できない要素 → 取込報告
   ▼
 [5 既存の取込] 素材の照合・オフライン化・再リンク、新しい .fcproj
   │
   ▼
 編集画面／CLI／エージェント（同じ取込命令）

 照合用の正解：同じ見本案件からPremiereが書き出した FCP7 XML
             → 既存の FCP7 読込 → 4 の結果とシーケンスを比較
```

## データと処理境界

1〜4は `crates/interchange` の新しいモジュール `prproj` に置き、ファイル入出力を持たない（L2の約束を守る）。`Format` に `Prproj` を加え、`detect` で拡張子とgzipの先頭を見て判定する。読込結果は既存の `Imported` と `Report` を使うので、5は `crates/engine/src/interchange.rs` の既存経路をそのまま通る。新しい依存はgzip展開とXML読取だけで、どちらも既に使っているクレートで足りるかを先に確認する。

段階ごとに受け入れる範囲を広げる。

| 段階 | 再現するもの | 出口 |
| --- | --- | --- |
| P0 見本 | 自社で作った見本案件と、同じ案件から書き出したFCP7 XML | 見本ごとの作成者・版・ライセンス・sha256を台帳に記録 |
| P1 容器と版 | 展開、上限、保存版の判定、拒否の理由 | 全見本で版を判定し、壊れたファイルを拒否する試験 |
| P2 骨格 | シーケンス、トラック、クリップ、In/Out、素材参照、fps、音声チャンネル | 正解XMLとフレーム単位で一致 |
| P3 編集の詳細 | 速度、切替、マーカー、ネスト、ビン、ラベル、複数シーケンス | 同上。未対応は報告に出る |
| P4 よく使う効果 | 位置・スケール・不透明度・音量など基本の調整 | 値の一致。それ以外の効果は名前と場所を報告 |
| P5 書き出し | `.prproj` の保存 | P4の結果を見て別途判断する |

## 既存実装との対応

方針は「新規設計」。対象マイルストーンは[M4](../../../development/milestones.md)。

上流コードの照合先：[crates/interchange/src/lib.rs](../../../../crates/interchange/src/lib.rs) の `Format`・`detect`・`import_with`、[crates/engine/src/interchange.rs](../../../../crates/engine/src/interchange.rs) の取込経路。

**クリーンルームの制約**。公開仕様がないため、構造は自社で作った見本案件からだけ読み取る。見本はPremiereのライセンスを持つ人が、Cutsetが生成した合成素材で作り、本人が許可されたライセンスで公開できるものに限る。エージェントはPremiereを操作しない（操作した場合はその会話でコードを書かない）。他の解析ツールの実装は読まない。Premiereの内部の名前を記憶から書かず、見本に現れた事実だけを使う。

編集画面・支援技術・エージェント操作の共通条件は[分野別の操作契約](../../shared/interaction.md)を適用する。
