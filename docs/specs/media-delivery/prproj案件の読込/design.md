# prproj案件の読込の設計（IO-57）

[要件](requirements.md) ・ [設計](design.md) ・ [作業・試験](tasks.md) ・ [分野一覧](../README.md)

## 操作と状態遷移

編集者は「ファイル ▸ 開く」または素材ブラウザーで `.prproj` を選ぶ。Cutsetは容器と版を確かめ、対応できれば新しい未保存の案件を作って取り込み、先頭にオフライン素材・欠落・値違いの件数を出した取込報告を表示する。対応できなければ、開いている案件を変えずに理由と代わりの経路を示す。CLIとエージェントは同じ命令を呼び、案件IDと報告をJSONで受け取る。

## データと処理境界

全体図は[編集ソフト間の引き継ぎの設計](../../workflow/編集ソフト間の引き継ぎ/design.md#データと処理境界)の[D][E][F]。

**置き場所（規約9・10）**。容器の展開・上限・版判定・型付きの読取は storytold/craft-libs に置き、`craft_timeline::interchange` の共通モデルを返す（新クレート `craft-prproj`、または `craft-timeline` の機能 `prproj`。他社案件ファイルを読む前例は `craft-aep`）。Cutset側の `crates/interchange` は `Format::Prproj` と `import_shared` への接続だけを持つ。変更は ①craft-libs ②Cutsetの `rev` 更新（単独のPR） ③Cutset側の接続、の3つに分ける。craft-libsへの提案が止まる場合の扱いはオーナーが決める（下の判断事項）。

**Cutset側の接続**。

- `Prproj` はAAF・OMFと同じくバイナリとして扱い、`import_with` の文字コード変換（`decode_text`）より前で分ける。
- `detect` は先頭が gzip の印（`1f 8b`）で拡張子が `prproj` のときだけ `Prproj` を返す。中身はP1の読取で確かめる。
- `Format` に書き出し可否（`can_export`）を加え、`Prproj` は書き出しの選択肢に出さない（IO-58で切り替える）。
- `crates/engine/src/interchange.rs` の `EXTENSIONS` と素材ブラウザーに `prproj` を加える。今の取込は開いている案件への合流なので、新しい案件として開く命令を加える。

**上限と不正入力**。

- 展開は許可リストにある `flate2`（`rust_backend`。wasm32でも動き、`crates/export` が既に使う）で行う。圧縮前64 MiB、展開後512 MiBを上限とし、上限＋1バイトまで読んで超過を検出したら `TooLarge` で止める。gzipの検査値（CRC32と元の長さ）を確かめ、複数メンバーや末尾の余計なデータは見本で確認するまで拒否する。
- XMLは craft-xml の厳格な設定で読み、文書型宣言は拒否する。ノード数・深さなどの上限は見本の最大値の4倍を根拠として定数にし、根拠を注記する。
- 上限超過や構造の誤りは `Error` で、途中までの結果を返さない。要素単位の欠落だけを報告に入れる。非試験コードはパニックしない。

**相互参照**。IDの索引は一度だけ作る。IDの重複は文書全体を拒否する。参照先の欠落は、その要素を空白またはオフラインにして報告する。参照は訪問済みの集合を使って反復で解決し、入れ子の深さは既存の `MAX_NESTING_DEPTH`（64）以下にする。同じシーケンスへの参照は一つに畳み、生成するクリップの総数に上限を置く。自分自身を含むシーケンスは既存の方針どおり空白にして報告する。

**版と未知の要素**。版の許可表は「版の値・その版の見本のsha256・確認日」の定数表にし、版の値を読む位置は見本から台帳に記録する。未確認の版は版の値を示して拒否する。読取は確認済みの要素の経路だけをたどり、未知の子要素は経路ごとに件数を情報として集計する。必須の値が欠けた要素は既定値で埋めず、その項目を省いて警告にする。時間の単位は見本から導き、記憶から仮定しない。

**読取の木構造（IO-58のための判断）**。P1で、未知の節点を捨てずに保持する木構造を採るかを決めて記録する。保持すれば将来の書き出しで「読み込んだ木を変えた部分だけ書き換える」方式が取れる。

**取込報告**。各項目に要素キー（[要素一覧](../../workflow/編集ソフト間の引き継ぎ/requirements.md#受入条件)と共通）と場所（シーケンス名・トラック番号・クリップ番号）を持たせる。試験は文言ではなくキーと場所で確かめる。`ReportEntry` を拡張する場合は、FCP7・AAFの既存試験が通ることを同じ変更で確かめる。

### 照合の基準

両方の読込結果を共通モデルに正規化し、シーケンスごとに比べる。

- **一致とする項目**：シーケンス名・フレームレート・画面サイズ・開始タイムコード（ドロップ／ノンドロップを含む）、種類別のトラック数と順序、クリップごとの「トラック番号・配置のIn/Out・素材のIn/Out・素材の同一性・速度・有効状態・リンクの組」。
- **時間**：`Tick` で比べる。29.97 fpsの1フレームは 8,475,667,200 Tick（254,016,000,000 × 1001 ÷ 30000）で割り切れるので、映像は完全一致を求める。フレーム境界にない値は丸めずに報告する。音声の端はサンプル精度とし、XML側との差は既知の差として記録する。
- **素材の同一性**：URLを復号してNFCに正規化した絶対パスで比べる。
- **集合**：両方向の集合一致。片方にしかないクリップは不一致。内部IDと要素の並び順は比べない。
- **数値の許容差**（作成票との比較）：速度±0.01%、不透明度±0.1%、音量±0.05 dB、位置±0.5 px、キーフレームの時刻は0フレーム差。許容差はCutset側の値として決める。
- 見本1〜3は、作成票から手で書いた期待値も持つ（読込器同士の比較だけにしない）。
- 比較関数は試験用の補助（`tests/it/support`）に一つだけ置き、UX-15の試験でも同じものを使う。

| 段階 | 再現するもの | 出口 |
| --- | --- | --- |
| P1 容器と版 | 展開、上限、版判定、拒否の理由、木構造の方針の決定 | 全見本で版を判定し、不正入力の表をすべて拒否する |
| P2 骨格 | シーケンス設定、開始タイムコード、トラック、クリップ、In/Out、素材参照、音声チャンネル | 照合の基準で正解XMLと一致 |
| P3 編集の詳細 | 速度、切替、マーカー、ネスト、ビン、ラベル、複数シーケンス | 同上。ビン・ラベルは作成票と一致 |
| P4 基本の調整 | 位置・スケール・回転・不透明度・音量・パンの値とキーフレーム | 作成票と許容差内で一致。それ以外の効果は要素キーと場所を報告 |

**判断事項（オーナー）**。craft-libsへの変更は上流のレビューを経る。上流への提案が長く止まる場合に、Cutset側で先に実装して後で移すか（規約9からの逸脱としてPRに理由を書く）を、H1判定と同時に決める。
