## 実装と検証

ハーネスの作業IDは `BUILD-IO-57`、受入IDは `AC-IO-57`。各段階の試験は `crates/interchange/tests/it/prproj.rs` に置き、段階ごとにグラフへ作業とRustの検査を登録する。

- [ ] P0 見本：下の一覧の案件を作成者が作り、同じ案件からFCP7 XMLも書き出す。版・作成者・ライセンス・sha256を台帳に記録する。
- [ ] P1 容器と版：展開・上限・版判定・拒否理由を実装する。
- [ ] P2 骨格：シーケンス・トラック・クリップ・素材参照を正解XMLと比べる。
- [ ] P3 編集の詳細、P4 よく使う効果：範囲を広げるたびに報告の件数が減ることを確かめる。
- [ ] 編集画面・CLIで開き、取込報告の表示、原本のハッシュ不変、保存・再読込を確認する。

## 具体的な試験

見本案件の一覧（素材はすべてCutsetの合成素材、25 fpsと29.97 fps）：

1. 1シーケンス・1クリップ（最小）
2. 映像2トラック・音声3トラック、空白とリンクした音声
3. 同じ素材の別配置、In/Outの異なる切り出し
4. 速度50%・200%・逆再生
5. ディゾルブなどの切替、フェード
6. シーケンスマーカーとクリップマーカー、ビンの入れ子、ラベル色
7. ネストしたシーケンスと複数シーケンス
8. 位置・スケール・不透明度・音量のキーフレーム
9. 素材を移動してオフラインにした案件、日本語のファイル名・シーケンス名
10. 異なる2つの保存版で同じ内容を保存したもの

壊れた入力：途中で切れたgzip、XMLの閉じ忘れ、巨大な展開サイズ、深すぎる入れ子。いずれも案件を作らずに理由を返し、パニックしない。上流の不正入力の総当たり試験にも加える。
