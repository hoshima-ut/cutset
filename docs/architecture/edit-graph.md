# 編集候補の影響範囲と確定

対象は複数のカット案を一度に適用する機能です。試聴中に保持する状態、変更の影響を受ける配置、Undoの単位を定めます。既存の実装には案件内ID、リンクされた配置、編集履歴があります。候補の版照合と再送処理はCutsetで追加する設計です。[上流の編集エンジン](../../crates/engine/src/lib.rs) ・ [区間を詰める既存演算](../../crates/edit/src/transcript.rs)

## 参照する関係

| 始点 | 参照先 | 確定時の判断 |
| --- | --- | --- |
| 配置 | 所属トラック、元素材、素材内の区間 | 同じ素材の別配置を区別し、素材時刻とシーケンス時刻を別々に検証する。 |
| 配置 | リンクされた映像・音声 | リンクを保つ変更では両方の範囲とロック状態を確認する。片側だけ適用できる場合は確定を止める。 |
| トラック | 配置・字幕・同期移動対象 | 編集区間に重なる項目と、区間より後で時刻が変わる項目を列挙する。固定した音楽は元位置を保つ。 |
| ネスト配置 | 子シーケンス | 子の内容を変更する操作と、親で参照区間だけを短縮する操作を区別する。 |

各候補は対象シーケンスのID、基準版、対象の配置ID、時刻の座標系、元区間、変更後の区間を持ちます。時間はエンジンのtickで保持し、フレーム表示にはシーケンスの有理数フレームレートを使います。区間は開始を含み終了を含みません。

## 試聴から確定まで

1. 現在の案件を読み、候補ごとに変更対象と、影響によって移動する項目を計算します。試聴用の配置表をUIに返します。この段階では案件の変更状態とUndo履歴を更新しません。
2. 編集者が保留・採用を選びます。重なる削除区間を二重に数えず、選択を変えるたびに結果の尺と残す区間を再計算します。
3. 確定要求には操作ID、基準版、採用候補を渡します。確定直前に対象、素材参照、トラックのロックを再照合します。基準版が変わった場合は再評価を要求し、新しい差分を確認できるようにします。
4. 検証済みの変更を一つのエンジン編集として適用します。途中失敗は全変更を取り消します。成功時には操作IDと結果を関連付け、同じ要求の再送には既存の結果を返します。同じ操作IDで内容が異なる要求は競合とします。Undo後に届く再送も自動で再適用しません。

## 入出力の照合例

25 fps、1,600フレームの案件で、元位置の [205,245) と [505,565) を詰めます。元位置 [800,825) は残します。短縮は100フレーム、残した区間は [700,725)、映像終端は1,500です。後続時刻から既に除去した区間長を引くため、二つ目の削除位置を一つ目の削除後の座標として再解釈しません。固定した音楽が映像より長い場合は、その終端も含めて案件の尺を決めます。

| 試験条件 | 期待する観測 |
| --- | --- |
| 試聴後に対象トラックをロック | 確定を拒否し、変更と履歴追加が0件。 |
| 同じ採用要求を二度送信 | 最初の成功結果を再利用し、二回目の短縮が0フレーム。 |
| 採用後のUndoとRedo | 元の尺・配置関係を復元し、Redo後は同じ採用結果に戻る。 |
| 途中で対象配置が見つからない | 一部だけ編集された案件を残さず、消えた対象のIDを返す。 |

現在のフレーム計算は[基準案件の記録](../development/progress.md)で確認できます。GUIでの聴き比べ、選択確定の原子性、再起動をまたぐ再送の検証は各作業表で追跡します。
