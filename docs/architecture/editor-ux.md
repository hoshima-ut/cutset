# 最速で編集できる画面の設計

版1.1（2026-11-29）。オーナーから「最強・最速で、最も編集者に寄り添ったUI/UXを作り、評価して進めてよい」と委任された。判断の根拠・評価・採否はこの文書と各Issueに残す。見た目の方針は[デザインのDNA](../development/visual-identity.md#デザインのdna)。

1.1の主な変更：4つの視点のレビュー（放送の編集者、初めて触る人、キーボード中心の人、アクセシビリティ）を反映した。素材の自動再接続を厳密な一致に限る、反応の計測をP0に上げる、ホームを独立したキーの範囲にして日本語入力と衝突させない、山吹色の役割を二つに絞る、命令を探す入口の仕様とキー、初めての人の最初の一分、手数と反応の測り方を加えた。採否は末尾の表。

## 原則

1. **起動から編集まで1キー**。ホームは前回の案件を選んだ状態で開き、Returnで開く。キーボードだけで全部の操作ができ、待たせない。ホームを飛ばして前回の案件を直接開く設定も残す。お試し案件は自分から選んだときだけ開く。
2. **開く前に分かる、開いたら待たない、間違った素材はつながない**。ホームで見つからない素材をボリューム単位で示す。再接続は案件を開いたまま裏で進めるが、自動でつなぐのは厳密に一致したものだけ。
3. **失わない、壊れない**。保存の状態を常に見せ、復旧の版を中身を比べてから別名で開ける。保存は今の原子的な方式を保つ。
4. **手が覚えた操作を壊さない**。パネルの配置と既定のキー、用語はPremiereと同じ型を保つ。変えるのは手数が測って減る所だけ。
5. **探さずに見つかる**。命令を名前で探して実行でき、結果にキーを併記する。よく使う操作は文字付きのボタンにも置く。
6. **反応は手より速く**。再生ヘッドと値の操作は次の画面更新までに追従させる。値のドラッグは一回の取り消しで戻る。
7. **選んだ物に道具が付いてくる**。属性欄は選択に追従し、複数選択では共通の値をまとめて変えられる（操作の型はFigmaを参考にする）。

## ホームの設計

ホームは「次の一手を一番早く出す画面」。編集の作業ではないので、配置を自由に作れる。[デザイン案](https://claude.ai/artifact/9j5EsmgYDjR7G9ZhgAoZMK)

**状態**。

| 状態 | 見せるもの | Return | Esc |
| --- | --- | --- | --- |
| 初めて | 空のタイムラインがそのまま素材の落とし先。縦・横・正方形の選択（素材に合わせるのが既定）と保存先 | 読み込みの窓を開く | 何もしない |
| 案件がある | 最近の案件の一覧。前回の案件を選んだ状態 | 選んだ案件を開く | 案件が開いていれば編集画面へ戻る |
| 絞り込み0件 | 「一致する案件はありません。Cmd+Oでほかの案件を開く」 | 何もしない | 絞り込みを消す |
| 開いている途中 | 進み具合と、何を待っているか | — | 取りやめる |
| 素材が見つからない | ボリューム単位の件数と前回の場所。再接続の候補 | 開いて裏で再接続する | 戻る |
| 開けない・壊れている | 理由。復旧の版ごとの保存日時・シーケンス数・最後に触ったシーケンス・総クリップ数 | 選んだ復旧の版を別名で開く | 戻る |

Escは「絞り込みを消す → 開いている途中を取りやめる → 編集画面へ戻る」の順に一つだけ働く。

**一覧の各行**。実際の一コマ、プロジェクト名、尺（「1分04秒」のように人が読む形）、置き場所（ボリューム名と親フォルダー）、最後に開いた日時、最後に開いていたシーケンス名と再生位置、他の人が開いているか、素材の状態。素材の確認は前回の結果を先に出して裏で更新し、確認が終わっていなくても開ける。最近の案件が1件でもあれば、お試し案件は一覧から外してメニューにだけ置く。よく使う案件を上に留められる。→キーで、その案件のシーケンスを選んで直接開ける。

**キーと焦点**。ホームは独立したキーの範囲（`Home`）とし、修飾キーのないキーは編集画面の割当に渡さない。素通しするのはCmdを含むアプリ全体の命令（Cmd+O、Cmd+I、Cmd+Alt+N、Cmd+Q、Cmd+,、命令を探す入口）だけ。焦点は常に絞り込み欄にあり、↑↓は欄に焦点を残したまま一覧の選択を動かす。文字は欄に入る。日本語入力の変換中（未確定から確定まで）は、Return・Esc・↑↓・TabをIMEに渡し、ホームの操作にしない。絞り込みは確定した文字で、かな・カタカナ・大文字小文字を区別せずに行う。Tabの順は「絞り込み欄（一覧を含む）→ 開く → 場所を指定 → ほかの案件を開く → 新しい案件 → 素材を読み込む → XMLから続ける」。案件がない状態のCmd+Iは無題の案件を作って読み込み、作ったことを見出しに出す。未保存の案件がある状態の新規・開くは、既存の保存確認を通す。

**色と形**。山吹色は再生ヘッドと「選択中の印」だけ。焦点はテーマの焦点色の2px枠で、全画面で共通にする。主ボタン「開く」はロゴの紫。選択は背景に加えて山吹色の枠で示し、焦点が外れても形で残る。輪郭はテーマの `field_border`・`button_border`（3:1以上）を使う。ロゴだけをテープ状の名札に載せて少し傾け、読む文字は水平に置く。書体は見出しの丸ゴシック、本文、数字用の等幅の3役まで。画面に出すキーは、使っている割当から作り、文字で直接書かない。OSの「視差効果を減らす」がオンなら、動きを止めて即座に切り替える。

**読み上げ**。一覧はListBoxとListBoxOption（選択状態つき）、行の名前は見えている順に「プロジェクト名、尺、置き場所、最後に開いた日時、素材の状態」。絞り込み欄の名前は「案件を絞り込む」。キーは名前に入れず、ショートカットとして出す。素材の確認や保存状態の変化は丁寧な通知（polite）、開けない状態は割り込みの通知（assertive）で知らせる。

## 命令を探す入口

既定キーはCmd+Shift+P、別名Cmd+J。既定とPremiere互換の両方の割当で空いていることをソースで確認した（Cmd+Kは再生位置でカット、Cmd+/はPremiere互換の新規ビン、Cmd+Pはポスターフレームで使用中）。UI側で登録する命令を含む全割当と、Adobeの公開のキー一覧での最終照合は実装時に行う。

1. 全命令を対象にし、翻訳後の表示名・英語の表示名・メニューの経路・命令ID・別名（Premiereの用語。例「カット」「Add Edit」）で照合する。
2. 大文字小文字を区別しない飛び石の一致。単語頭の一致、連続した一致、飛び石の順に並べ、同点は最近使った順、有効な命令を先にする。
3. 開いた直後は最近実行した命令を最大8件。キーやメニューからの実行も数える。記録は利用者の設定に保存する。
4. 使えない命令は後ろに回し、理由を一行添える（例「シーケンスが開いていません」）。命令の登録に使えない理由を返す仕組みを加え、理由のない命令は「今は使えません」と出す。成功に見せない。
5. 今の割当のキーを右端に出す。パネル限定のキーは範囲を添える。同名の命令にはメニューの経路を添える。
6. 有効かの判定と実行は、入口を開く直前に焦点があったパネルを文脈にし、実行後は焦点をそこへ戻す。
7. 「…」で終わる命令は既存の窓を開く。必須の引数は入口の中で次の入力段に進む。選択から決まる引数は自動で埋めて表示する。
8. ↑↓で選び、Returnで実行、Escで閉じる。Cmd+Returnは実行して開いたままにする。

## 初めての人の最初の一分

- タイムラインの上の道具帯に、文字付きの「分割 ⌘K」を置く。道具のアイコンは、ポインターを置くと名前とキーを出す。
- 最初の3回の起動に限り、下の帯に次の一手を一行ずつ出す（素材を置く → 再生 → 分割 → 要らない所を消す）。閉じると、もう出さない。全画面の案内や吹き出しの連続は使わない。
- 空のパネルには、空の理由と埋め方を書く。
- 用語はPremiere日本語版と同じにする。主な利用者がPremiereに慣れているため。説明は空の状態と案内の文で補う。

## 評価のしかた

判断を委任されているため、次で評価し、結果をIssueに残す。

1. **編集者の視点のレビュー**。今回の4つの視点で、画面を作るたびに独立にレビューし、指摘と採否を記録する。
2. **手数**。基準案件で、次の作業の手数と秒数を変更前後で数える。

| 作業 | 開始 | 終了 |
| --- | --- | --- |
| 前回の続きを再生する | アプリの起動（冷えた起動と温まった起動を分ける） | 再生が始まり最初のコマが出る |
| PremiereのXMLを開いて続きを再生する | XMLを開く操作 | 再生が始まる |
| 素材を読み込んで最初のカットをする | ホーム | 最初の分割 |
| リップルトリムで尺を1秒詰める | 対象の編集点を選ぶ | 確定 |
| テロップ5枚の文言を差し替える | 最初のテロップを選ぶ | 5枚目の確定 |
| 共有ボリュームが外れた状態で開いて再接続する | ホームで選ぶ | 全素材がオンライン |
| 音声仕上げ用のAAFとガイド映像を書き出す | 書き出しを開く | 書き出しの開始 |

数え方：キー1回は修飾キーを含む一つの組み合わせ。文字は1文字1回、日本語入力の変換・確定キーも数える。クリック・ドラッグ・一続きのスクロールは各1回、ポインターの移動は数えない。キーボードとポインターの持ち替えは別に数える。秒数は実時間で、操作を受け付けない時間を「待ち秒」として別に記す。手順は台本どおりに制御チャンネルから機械で流して測り、人の試行は参考値として分ける。キーを知っている人の最短経路と、画面の表示だけを頼りにした経路の両方を数える。基準案件は64秒の[パイロット](../verification/interview.md)に加え、2時間・素材500本・共有ストレージ上の大きい案件を合成素材で用意する。

3. **反応の測り方**。(a) 合図の遅れ＝入力イベントの時刻から、それを反映した画面を表示に渡すまで（再生ヘッドの線、値の数字、選択枠）。(b) 中身の遅れ＝同じ起点から、その位置の正しい一コマが出るまで。ミリ秒と画面更新の回数（60Hzで16.7ms＝1回）で、p50・p95・p99と取りこぼした更新数を報告する。合格の線は(a)p95が1回以内、p99が2回以内。(b)は素材が手元にあればp95が2回以内、デコードが要る場合は別に記録する。基準機を1台に固定し、アプリ内の時刻の記録を制御チャンネルの操作で再現できる手順にする。節目ごとに一度、240fpsの撮影で外から確かめる。対象は再生ヘッドのドラッグ、一コマ送り、J/K/L、値のドラッグ、タイムラインの拡大縮小。
