# マイルストーン

完了は各行の出口を人が確認したときに記録する。日付は編集者試験の結果を見て設定する。直近の一手と担当交代の情報は[作業台](../handbook/tasks.md)。この表を版管理し、GitHub Issueを使う場合は一つの担当・受入条件を持つ実装タスクだけを切り出し、仕様IDを添える。

| 節目 | 前提 | 編集者ができること・出口 | 確認方法 |
| --- | --- | --- | --- |
| M0 開発開始 | 公開fork | 現在の機能から仕様と検証をたどり、秘密情報を含めず手元で変更を検査できる | ローカルで文書・仕様グラフを検証し、同じコミットで試聴計画の回帰試験を再実行 |
| M1 試聴 | M0、基準インタビュー | A/B/Cの候補をキーで巡り、元の音と案を聴き、呼吸Cを残す。キャンセルでフォーカス・原版保持 | フレーム試験に加え、編集者がGUIで試聴し結果を記入 |
| M2 一回で確定 | M1 | A/B採用で1,600→1,500フレーム。ロックしたBGM、字幕、保存再開、書き出しを照合し、一度のUndoで戻す | ローカルエンジン・GUI・CLI同一案件。競合、二重適用、途中失敗試験 |
| M3 AIを選ぶ | M2、モデル接続仕様 | ローカル文字起こしから始め、選択した接続先で同一形式の編集案を得る。素材、請求元、送信範囲を編集者が選べる | 偽プロバイダーで失敗経路、同意した実接続で一往復。操作時間・採否と手修正の理由を記録 |
| M4 別の編集室へ渡す | M2 | OTIO・SRT・参照動画で外部エディタへ渡し、一箇所修正して戻す。欠落・焼込み・要手直しを引渡票に明示 | アプリ名と版、fps、音声、フレーム位置、字幕の往復照合 |
| M5 プロ編集と配布 | M2、対象の機能仕様 | マルチカム・音声・色・グラフィック・書き出しを含む基準案件を一人で納品し、ブランド分離した配布物を導入・更新できる | 分野ごとの実機確認、ライセンスとOS別のインストール・更新・削除、旧案件を開く試験 |
| M6 Webレビューから共同編集へ | M4 | ブラウザで同じ版・フレームに注釈し、デスクトップで開く。次段階で粗編集、オフライン復帰、競合解決を個別に受け入れる | ブラウザ×案件能力表、WASMとネイティブで編集の再生結果を比較、別端末で復帰試験 |

M3・M4はM2の後に並行できる。M5は各分野を個別に昇格する。M6はレビュー、粗編集、同時編集を順番に解放する。残る仕様の優先度は案件の頻度と、失敗時に納品へ与える影響で更新する。

各機能の目標を[分野別仕様](features/README.md)と[機械可読台帳](catalog.json)の `milestone` に記録する。これは機能全体を評価する目標で、先行する断片的な実装やハーネス上の合格は個別タスクで追う。

M4の最初の交換対象をOTIOにしたのは、元素材と編集情報を分けて扱え、カット・タイミング・トラック・マーカーを照合できるから。映像や音声は外部参照なので、メディアの対応表と参照動画も一緒に渡す。[OpenTimelineIOのデータモデル](https://opentimelineio.readthedocs.io/en/latest/)
